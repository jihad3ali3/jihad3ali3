🧭 Engineering Principles
Understand the problem. Design the data. Build with intent. Refine continuously.

Clear requirements and a thoughtful data model make reliable software possible. I aim for readable code, deliberate decisions, and solutions that can evolve without becoming difficult to maintain.

<details> <summary><b>Four principles I work by</b></summary><br />
01 · Understand before building. The most expensive bug is the one written against the wrong requirement.

02 · Design the data first. Many downstream architecture problems begin with unclear schemas and relationships.

03 · Write for the next reader. Code is read far more often than it is written; clarity beats cleverness.

04 · Ship, then refine. Working software and feedback create better decisions than planning in a vacuum.
